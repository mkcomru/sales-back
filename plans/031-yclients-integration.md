# 031 — YClients: домен API онлайн-записи

## Objective

Шеф: «Мы работаем с мастерами перманентного макияжа. Они используют YClients для управления календарями. Нам нужно узнавать свободные слоты мастеров, учитывая что разные процедуры имеют разную длительность. Также нужно заполнять поля и создавать запись — имя, тип процедуры и т.д.»

## Зачем это делаем

- **Проблема:** Мастера перманентного макияжа ведут запись в YClients. Клиент пишет в чат, AI-агент отвечает, но записать клиента на приём не может — приходится вручную или перенаправлять.
- **Ценность:** Агент сможет прямо в диалоге показать свободные слоты, предложить время, собрать данные клиента и создать запись — без участия администратора. Полный цикл «лид → запись» внутри чата.
- **Что становится возможным:** Клиент выбирает процедуру, видит ближайшее свободное время, называет имя и телефон — запись создана за секунды.

---

## Домен YClients API

**Официальная документация:** https://developers.yclients.com/ru/  
**Base URL:** `https://api.yclients.com`  
**Rate limit:** 200 req/min, 5 req/sec на IP  
**Формат дат:** ISO 8601 (`2025-01-01T12:00:00+03:00`)  
**Длительности:** в секундах (15 мин = 900, 1 час = 3600, 2 часа = 7200)

### Авторизация

Два уровня:

```
Authorization: Bearer <partner_token>                      — для booking-эндпоинтов (достаточно)
Authorization: Bearer <partner_token>, User <user_token>   — для управления компанией
```

Partner token получается через маркетплейс интеграций: https://yclients.com/appstore/developers

Заголовок версии обязателен:
```
Accept: application/vnd.yclients.v2+json
```

**Для онлайн-записи user_token НЕ нужен** — все booking-эндпоинты работают только с partner_token.

### Ключевые сущности

| Сущность | Описание |
|----------|----------|
| **Company** (`company_id`) | Филиал/салон. Один партнёр может управлять несколькими. Все booking-запросы привязаны к company_id. |
| **Service** (`service_id`) | Услуга (например «Пудровые брови»). Имеет `seance_length` (длительность в секундах), `price_min`/`price_max`, принадлежит категории. |
| **Category** (`category_id`) | Группа услуг (например «Перманентный макияж»). |
| **Staff** (`staff_id`) | Мастер/сотрудник. `staff_id=0` означает «любой мастер». У каждого — расписание, рейтинг, специализация. |
| **Booking/Record** (`record_id`) | Созданная запись клиента. Содержит услуги, мастера, время, данные клиента. |
| **Seance** | Конкретный слот времени, доступный для записи. Имеет `time` ("14:00"), `seance_length`, `datetime`. |

## Эндпоинты раздела «Онлайн-запись»

Эти эндпоинты специально адаптированы для пользовательских сценариев записи (в отличие от REST-CRUD методов для интеграций).

### 1. Получить услуги — `GET /api/v1/book_services/{company_id}`

Возвращает услуги + категории, доступные для бронирования.

**Query params (все опциональные):**
- `staff_id` — фильтр по мастеру (только его услуги)
- `datetime` — фильтр по дате (формат ISO 8601, например `2025-09-09T18:30`)
- `service_ids[]` — если уже выбраны услуги, покажет совместимые

**Ответ (data):**
```json
{
  "category": [
    {"id": 1895571, "title": "Уходы для волос", "sex": 0, "weight": 60}
  ],
  "services": [
    {
      "id": 1896208,
      "title": "Мытье волос",
      "category_id": 1895571,
      "price_min": 0,
      "price_max": 0,
      "discount": 0,
      "comment": "",
      "weight": 0,
      "active": 0,
      "sex": 0,
      "image": "",
      "prepaid": "forbidden",
      "seance_length": 3600
    }
  ],
  "events": []
}
```

**Важно:** `seance_length` возвращается **только если задан фильтр по staff_id**. Без мастера — длительность не указана (она может отличаться у разных мастеров).

---

### 2. Получить мастеров — `GET /api/v1/book_staff/{company_id}`

**Query params:**
- `service_ids[]` — только мастера, оказывающие эти услуги
- `datetime` — только мастера со свободными сеансами в это время

**Ответ (data) — массив:**
```json
[
  {
    "id": "16",
    "name": "Вася",
    "bookable": true,
    "specialization": "Мастер перманентного макияжа",
    "position": {"id": 1, "title": "Администратор"},
    "show_rating": "1",
    "rating": "3",
    "votes_count": "1",
    "avatar": "",
    "comments_count": "0",
    "weight": "11",
    "information": "",
    "seance_date": 1443139200
  }
]
```

**Важно:**
- `bookable: true` — есть доступные сеансы. Если `false` — мастер работает, но нет свободных окон.
- `seance_date` — timestamp ближайшей даты с доступными сеансами (только для `bookable=true`).

---

### 3. Получить доступные даты — `GET /api/v1/book_dates/{company_id}`

**Query params:**
- `staff_id` — конкретный мастер (0 = любой)
- `service_ids[]` — услуги (важно для учёта длительности!)
- `date` — месяц (формат `2025-09-01`)
- `date_from`, `date_to` — диапазон дат (приоритет над `date`)

**Ответ (data):**
```json
{
  "booking_days": {
    "9": ["4", "5", "8", "9"],
    "10": ["1", "4", "5"]
  },
  "booking_dates": [1441324800, 1441411200],
  "working_days": {"9": ["4", "5", "8", "9"]},
  "working_dates": [1441324800, 1441411200]
}
```

**Разница:** `working_days` — когда мастер/салон работает. `booking_days` — когда есть **свободные** слоты на выбранные услуги. Для записи нужен `booking_days`.

---

### 4. Получить свободные слоты — `GET /api/v1/book_times/{company_id}/{staff_id}/{date}`

**Path params:**
- `staff_id` — мастер (0 = любой)
- `date` — дата в формате `YYYY-MM-DD`

**Query params:**
- `service_ids[]` — услуги (**критически важно** — без них слоты не учитывают длительность процедуры!)

**Ответ (data) — массив:**
```json
[
  {"time": "12:00", "seance_length": 3600, "datetime": 1443513600},
  {"time": "13:00", "seance_length": 3600, "datetime": 1443517200},
  {"time": "14:00", "seance_length": 3600, "datetime": 1443520800}
]
```

**Ключевой момент для задачи шефа:** API **сам** рассчитывает доступные слоты с учётом длительности выбранных услуг. Если процедура 2 часа, а у мастера свободно с 14:00 до 15:30 — этот слот не вернётся. Не нужно самим считать пересечения.

`datetime` — unix timestamp, его нужно передать в `book_record` при создании записи.

---

### 5. Ближайшие сеансы мастера — `GET /api/v1/book_staff_seances/{company_id}/{staff_id}/`

Шорткат: вместо `book_dates` + `book_times` возвращает ближайшую дату + слоты сразу.

**Query params:**
- `service_ids[]`

**Ответ (data):**
```json
{
  "seance_date": 1492041600,
  "seances": [
    {"time": "10:00", "seance_length": 3600, "datetime": 1492063200},
    {"time": "10:15", "seance_length": 3600, "datetime": 1492064100},
    {"time": "10:30", "seance_length": 3600, "datetime": 1492065000}
  ]
}
```

Полезно для сценария «когда ближайшее свободное время?» без указания конкретной даты.

---

### 6. Проверить параметры записи — `POST /api/v1/book_check/{company_id}`

Валидация перед созданием. Позволяет поймать проблемы без побочных эффектов.

**Request body:**
```json
{
  "appointments": [
    {
      "id": 1,
      "services": [331],
      "staff_id": 6544,
      "datetime": 1443612600
    }
  ]
}
```

**Успех:** `201 Created`  
**Ошибки (HTTP 422):**
| Код | Ситуация |
|-----|----------|
| 433 | Слот уже занят |
| 436 | Нет доступных мастеров (при `staff_id=0`) |
| 437 | Пересечение с другой записью в этом же запросе |
| 438 | Услуга удалена |

---

### 7. Создать запись — `POST /api/v1/book_record/{company_id}`

**Request body:**
```json
{
  "phone": "79000000000",
  "fullname": "Анна",
  "email": "anna@example.com",
  "comment": "Первый раз",
  "notify_by_sms": 6,
  "notify_by_email": 24,
  "api_id": "external-id-777",
  "custom_fields": {
    "my_client_field": "value"
  },
  "appointments": [
    {
      "id": 1,
      "services": [331],
      "staff_id": 6544,
      "datetime": "2025-01-01 12:00:00",
      "custom_fields": {
        "my_record_field": 123
      }
    }
  ]
}
```

**Обязательные поля:** `phone`, `fullname`, `email`, `appointments[].staff_id`, `appointments[].datetime`  
**appointments[].id** — произвольный идентификатор для маппинга с ответом (не ID из БД).

**Успех — `201 Created`:**
```json
{
  "data": [
    {"id": 1, "record_id": 2820023, "record_hash": "567df655304da9b98487769426d4e76e"}
  ]
}
```

`record_id` — ID записи в YClients. `record_hash` — для удаления/просмотра без авторизации.

**Ошибки:**
| HTTP | Код | Ситуация |
|------|-----|----------|
| 422 | 431 | Неверный формат телефона |
| 422 | 432 | Неверный SMS-код подтверждения |
| 422 | 433 | Слот занят |
| 403 | 434 | Телефон в чёрном списке |
| 422 | 435 | Не указано имя |
| 422 | 436 | Нет доступных мастеров |
| 422 | 437 | Пересечение времени записей |
| 422 | 438 | Услуга удалена |

---

### 8. Перенос записи — `PUT /api/v1/book_record/{company_id}/{record_id}`

**Request body:**
```json
{"datetime": 1463754600, "comment": "Перенос по просьбе клиента"}
```

---

### 9. Получить запись — `GET /api/v1/book_record/{company_id}/{record_id}/{record_hash}`

Требует либо user_token, либо `record_hash` (выдаётся при создании).

---

### 10. Удалить запись — `DELETE /api/v1/user/records/{record_id}/{record_hash}`

---

### 11. SMS-подтверждение телефона — `POST /api/v1/book_code/{company_id}`

**Request body:**
```json
{"phone": "79991234567", "fulname": "Вася"}
```

Нужен **только если** `phone_confirmation=true` в настройках компании. Отправляет SMS с кодом, который затем передаётся в поле `code` при `book_record`.

## Формат ответов API

Все ответы обёрнуты в стандартную структуру:
```json
{
  "success": true,
  "data": { ... },
  "meta": []
}
```

При ошибке:
```json
{
  "success": false,
  "data": null,
  "meta": {"message": "Error description"}
}
```

## custom_fields (допполя записи и клиента)

Компания может создать свои дополнительные поля (через UI YClients). Каждое поле имеет `code` и `type` (number, string, list).

Передаются при создании записи двумя путями:
- **Поля клиента** — в корневом `custom_fields` объекта `book_record`
- **Поля записи** — в `appointments[].custom_fields`

Пример:
```json
{
  "custom_fields": {"source": "ai_agent"},
  "appointments": [{
    "custom_fields": {"preferred_intensity": "medium"}
  }]
}
```

## Типичный flow записи (последовательность API-вызовов)

```
1. book_services(company_id)                              → клиент выбирает услугу
2. book_staff(company_id, service_ids=[X])                → клиент выбирает мастера
3. book_dates(company_id, staff_id=Y, service_ids=[X])    → клиент выбирает дату
4. book_times(company_id, staff_id=Y, date, service_ids)  → клиент выбирает время
5. book_check(company_id, appointments)                   → валидация (опционально)
6. book_record(company_id, phone, name, email, ...)       → запись создана
```

**Альтернативный короткий flow:**
```
1. book_services → выбор услуги
2. book_staff_seances(company_id, staff_id, service_ids)  → ближайшие слоты сразу
3. book_record → запись
```

**Шаги можно менять местами** — например, сначала мастер, потом услуга. API поддерживает фильтрацию в обе стороны (услуги по мастеру, мастера по услуге).

## Доменные ограничения и edge cases

1. **Длительность процедур** — разные процедуры занимают разное время (30 мин, 1 час, 2 часа, 3 часа). API автоматически учитывает это при расчёте слотов, **но только если передать `service_ids`**. Без `service_ids` — вернутся все слоты без учёта длительности.

2. **SMS-подтверждение** — если компания включила `phone_confirmation`, flow усложняется (book_code → ввод кода → book_record). Для MVP рекомендуется работать с компаниями, где это выключено.

3. **Множественные услуги за один визит** — `appointments` — массив, можно записать на несколько услуг одним запросом. При этом `book_check` проверяет, что они не пересекаются друг с другом.

4. **`staff_id=0` (любой мастер)** — YClients сам назначит свободного мастера. Полезно, но клиент не будет знать к кому идёт до момента записи.

5. **Prepaid (предоплата)** — услуга может требовать предоплату (`prepaid: "required"` | `"allowed"` | `"forbidden"`). Если `required` — запись без оплаты невозможна. Нужен платёжный flow, который out of scope.

6. **Групповые события** — отдельный endpoint `POST /api/v1/activity/{company_id}/{activity_id}/book`. Отличается от индивидуальной записи. Для перманентного макияжа неактуально.

7. **Чёрный список** — если телефон клиента в чёрном списке компании, `book_record` вернёт 403/434. Агент должен корректно обработать.

8. **Rate limit per IP** — 5 req/sec. При нескольких параллельных клиентах одной компании можно упереться. Нужно учитывать при проектировании.

9. **Таймзоны** — компания имеет свой `timezone`. Все datetime в ответах — в таймзоне компании. При отображении клиенту нужно учитывать.

## Credentials, необходимые от клиента

Для работы интеграции клиент (владелец салона) должен предоставить:

| Параметр | Откуда взять | Обязательный |
|----------|-------------|--------------|
| `partner_token` | Маркетплейс интеграций YClients → Настройки аккаунта → API-ключ | Да |
| `company_id` | ID филиала (виден в URL панели YClients или через API) | Да |
| `form_id` | ID формы бронирования (из поддомена `https://w{form_id}.yclients.com`) | Нет (используется только для `bookform` настроек) |
