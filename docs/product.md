# Обзор продукта

**Платформа Sales Agent** автоматизирует многоканальные продажи с помощью AI-агентов и переиспользуемых модулей. Монорепозиторий содержит ядро AI Sales Agent, CRM‑специфические модули и общие библиотеки в каталоге `libs/`.

## Ключевые возможности
- Мгновенные AI‑ответы для CRM и чатов с помощью пайплайнов на OpenAI Agents SDK.
- Гибридные сценарии работы с знаниями: скриптованные FAQ‑диалоги, структурированная база знаний и управляемая передача менеджерам.
- Квалификация лида, маршрутизация и обновление стадии по событиям CRM.
- Модульная рамка, позволяющая подключать сервисы платформы (CRM и мессенджеры) через унифицированный транспортный слой.
- Надёжная доставка сообщений: Sales Agent формирует ответы и передаёт их в специализированные транспортные сервисы с HMAC‑подписью и идемпотентностью по `correlation_id`.
- Постоянное хранение контекста в Backend (Tortoise ORM, PostgreSQL).
- Управляемые через конфиг промпты (Markdown) для гибкой настройки поведения ассистента без кода.
- Опциональные интеграции с внешними сервисами (геолокация допустим) через реестр тулзов агента.

## Модули и роли
- **Backend (`apps/backend`)**: Центральный роутер и API‑сервис для управления конфигурацией платформы. Обрабатывает все потоки сообщений, управляет компаниями, продуктами, коннекторами, чатами и биллингом. Публикует события для event-driven обновления конфигурации.
- **Транспортные модули (`apps/telegram-module`, `apps/wappi-module`)**: отвечают за доставку готовых ответов в конкретные каналы (Telegram, WhatsApp и т. д.), управляют токенами, ретраями и режимами доставок. Получают конфигурацию из Backend и форвардят входящие сообщения в Backend.
- **Sales Agent (`apps/sales-agent`)**: Stateless LLM‑исполнитель — получает контекст от Backend, запускает tool loop, возвращает ответ; без БД и миграций; эскалации и обновление стадий — через write-only вызовы Backend API.
- **Общая библиотека (`libs/common`)**: общие конфиги, логирование и IO‑модели для единообразия поведения сервисов.

## Пользовательские сценарии
1. **Входящий диалог**: Транспортный модуль получает сообщение → отправляет в Backend (`POST /api/v1/messages/inbound`) → Backend валидирует auth, сохраняет в БД, при необходимости форвардит в Sales Agent → Sales Agent обрабатывает через LLM pipeline → отправляет ответ в Backend → Backend маршрутизирует на транспорт → транспорт доставляет в канал.
2. **Передача менеджеру**: агент обнаруживает критерии эскалации, уведомляет внешний прокси или сторонний endpoint, формирует человеко‑ориентированное резюме; при необходимости транспорт передаёт дополнительные поля (stage, handoff summary) в канал.

## Не входит в цели
- Ядро агента должно оставаться независимым от конкретного коннектора.
