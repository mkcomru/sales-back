# Схема диалогового пайплайна

Этот документ описывает архитектуру диалогового пайплайна Sales Agent, включая маршрутизацию между агентами и flow подбора продуктов.

## Общая архитектура

Пайплайн реализован на базе **кастомного LLMClient** с собственным tool loop. Маршрутизация выполняется через Router, который направляет запрос к соответствующему агенту:

```
┌────────────────┐
│  Входящее      │
│  сообщение     │
└───────┬────────┘
        │
        ▼
┌────────────────┐     light_llm_client        ┌─────────────────┐
│     Router     │ ─────────────────────────►  │  RouterDecision │
│  (chat_parse)  │   structured output         │  route + stage  │
└───────┬────────┘                             └─────────────────┘
        │
        ▼ route = "qualifier" / "category_expert"
┌────────────────────────────────────────────────────────────────────────┐
│                          Основной flow                                 │
├─────────────────────────────────┬──────────────────────────────────────┤
│           Qualifier             │           Category Expert            │
│   (large_llm + tool_loop)       │   (large_llm + tool_loop)            │
└─────────────────────────────────┴──────────────────────────────────────┘
        │
        ▼
┌────────────────┐
│    Handoff     │
│  (передача)    │
└────────────────┘
```

## Category-First Product Search Pipeline

### Обзор

Новый подход к подбору продуктов:

1. **Qualifier** определяет категорию (`category_id`), а не конкретный продукт
2. **Category Expert** использует тулзу `search_product` для поиска продуктов в категории
3. После выбора клиентом — собираются product-level поля
4. Финальный handoff с полной информацией

### Детальная схема

```
┌───────────┐   category_rules    ┌─────────────────┐   search_product   ┌──────────────┐
│ Qualifier │ ─────────────────►  │ Category Expert │ ─────────────────► │  Предложение │
└───────────┘   определяет        │                 │   (тулза)          │   продуктов  │
               category_id        │                 │◄─────────────────  └──────────────┘
                                  │                 │   клиент выбирает        │
                                  │                 │   selected_product_id    ▼
                                  │                 │   product fields    ┌──────────────┐
                                  │                 │◄──────────────────  │   Handoff    │
                                  └─────────────────┘                     └──────────────┘
```

### Этапы flow

#### 1. Qualifier → category_id

Qualifier собирает базовую информацию о клиенте и определяет категорию интереса.

**Механизм определения категории:**
- Используются `category_rules` из конфигурации компании
- Правила содержат условия (`when`) и результат (`category_id`)
- При совпадении ответов клиента с условиями — устанавливается `category_id`

**Пример правила:**
```json
{
  "when": {
    "destination": "Кавказ",
    "difficulty": "easy"
  },
  "category_id": 3
}
```

**Гейт перехода:** `_ready_for_category_expert()`
- `category_id` определён (явно или через правила)
- Базовые поля компании собраны (для CRM-коннекторов)

#### 2. Category Expert → search_product

Category Expert работает с выбранной категорией и подбирает продукты через tool loop.

**Тулза `search_product`:**
- Получает категорию и фильтры из ответов клиента
- Сопоставляет атрибуты продуктов с запросом
- Поддерживает fuzzy-поиск по названию/описанию
- Возвращает список подходящих продуктов с релевантностью

См. [llm-architecture.md](llm-architecture.md) для деталей реализации тулзы.

#### 3. Выбор продукта → selected_product_id

После предложения вариантов:
1. Клиент выбирает конкретный продукт
2. Category Expert сохраняет `selected_product_id` через `set_customer_fields`
3. Активируются product-level поля для сбора

**Доступные плейсхолдеры после выбора:**
- `{company.selected_product.name}` — название выбранного продукта
- `{company.selected_product.description}` — описание
- `{company.selected_product.fields}` — поля для сбора на уровне продукта

#### 4. Product fields → Handoff

После сбора product-level полей:
1. Формируется полный профиль клиента
2. Выполняется передача менеджеру (handoff)
3. Резюме включает: контактные данные, выбранный продукт, собранные предпочтения

## Состояния клиента

| Поле | Описание | Кто устанавливает |
|------|----------|-------------------|
| `category_id` | ID категории интереса | Qualifier (через category_rules) или явно |
| `selected_product_id` | ID выбранного продукта | Category Expert (после выбора клиентом) |
| `customer_answers` | Собранные ответы | Все агенты через `set_customer_fields` |

## Конфигурация

### category_rules

Правила определения категории хранятся в настройках компании:

```json
{
  "category_rules": [
    {
      "when": {"destination": "Кавказ"},
      "category_id": 3
    },
    {
      "when": {"destination": "Алтай", "difficulty": "hard"},
      "category_id": 5
    }
  ]
}
```

### Product attributes

Атрибуты продуктов для матчинга с ответами клиента:

```json
{
  "id": 1,
  "name": "Тур на Эльбрус",
  "category_id": 3,
  "attributes": {
    "destination": ["Кавказ", "Эльбрус"],
    "difficulty": ["easy", "medium"],
    "max_price": 45000,
    "dates": ["2025-07-01", "2025-07-15"]
  }
}
```
