## Особенности реализации

### JWT Tokens
- **Access Token**: короткоживущий (15 минут по умолчанию), содержит `user_id` и `is_superuser`
- **Refresh Token**: долгоживущий (30 дней по умолчанию), хранится в БД с JTI для отзыва

### Безопасность
- Пароли хешируются с помощью bcrypt
- Email хранится в lowercase для case-insensitive поиска
- Refresh токены можно отозвать индивидуально или все сразу
- Истекшие токены автоматически удаляются при проверке

### Graceful Degradation
- Logout не выбрасывает ошибку при невалидном токене (idempotent)
- Повторный logout с тем же токеном не выбрасывает ошибку

### RBAC (Role-Based Access Control)
- Роли: OWNER > ADMIN > VIEWER
- Суперпользователи получают автоматический доступ ко всем компаниям
- Проверка иерархии ролей при доступе к ресурсам

## Конфигурация

Тесты используют следующие переменные окружения:
- `AUTH__JWT_SECRET_KEY`: тестовый секретный ключ для JWT
- `AUTH__JWT_ALGORITHM`: алгоритм подписи (HS256)
- `AUTH__ACCESS_TOKEN_EXPIRE_MINUTES`: время жизни access токена
- `AUTH__REFRESH_TOKEN_EXPIRE_DAYS`: время жизни refresh токена

## База данных в тестах

- SQLite in-memory для быстрых тестов
- Автоматическая очистка между тестами
- Все схемы PostgreSQL удалены для совместимости с SQLite
